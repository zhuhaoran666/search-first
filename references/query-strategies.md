# 查询策略与恢复

按问题读取对应部分，不要求每次执行全部策略。下面的查询是构造示例，不是已验证的搜索结果或必须使用的服务。

## 从 idea 到检索问题

模糊 idea 往往没有包含资源库实际使用的名称。先用用户的目标和场景发现正式叫法，再沿这些名称找具体对象；不要只给原话加上“方案”或“资料”重复搜索。

例如用户说：“我想把读过的文章连起来，方便写东西时找到以前看过的内容。”

- 精炼表述：“你希望把读过的文章按主题或关联组织起来，并在写作时快速找回相关内容；先找现成的组织与检索方案。”不先假定必须开发软件、使用知识图谱或接入大模型。
- 第一轮可围绕功能发现术语：`organize read articles retrieve related notes`、`文章 关联 笔记 检索`；这些只是探索用词，不是已证实的最佳方案。
- 根据真实结果出现的术语，再查相关工具、工作流或实现案例。若出现“反向链接”“全文检索”等名称，核对其实际能力与场景，再决定是否沿该方向深入。
- 结果反馈应说明哪类现有方案覆盖了哪些需求、哪里仍需适配，而不是仅列一串关键词。用户没有说明离线或隐私要求时，可说明这些因素会影响选择，不直接把它们当作硬条件。

若用户的 idea 涉及可行性或效果，除了找支持材料，也寻找适用前提、失败案例或限制，避免把检索做成替预设结论找理由。若需要系统性的创新评价或文献综述，再按用户需求使用相应专门工作流，普通 idea 检索不自动升级。

## 结果太泛或找不到

| 观察 | 下一步 | 避免 |
| --- | --- | --- |
| 一堆概念介绍，没有成品 | 加对象类型，如 `template`、`download`、`repository`、`dataset`，或去相应资源库站内搜索 | 继续只搜索宽泛主题 |
| 精确查询为零 | 检查拼写、中文译名、缩写、年份或版本；去掉一个不确定的修饰词，保留核心实体 | 得出“没有这个东西” |
| 结果很多但全是广告/搬运 | 换原作者、机构或仓库路径，必要时限定域名或排除特定噪声词 | 把重复转载当独立证据 |
| 仅一篇文章提到目标 | 提取目标的专名、作者、原始链接、参考文献，继续追踪 | 把“有人提到”当成已获得目标 |
| 中文结果缺乏专业资源 | 用正式英文术语或资源原始语言搜索；国内规范/本地政策仍保留对应中文入口 | 机械逐字翻译，或完全丢掉地域条件 |
| 页面无法读取 | 在工具权限内尝试正常页面读取、浏览器、官方镜像或公开版本，并标出是否同一版本 | 绕过访问控制或把失败页面当作看过 |
| 工具不支持所需语法 | 改用工具原生过滤参数或短词查询，再根据返回结果细化 | 假定所有工具都支持相同搜索运算符 |

`site:`、引号、排除词、`filetype:` 是可选策略，只在当前入口支持时使用。过早限定文件类型会漏掉提供文件的 HTML 入口页；过早限定日期会漏掉仍然适用的经典资源。

## 按对象追踪

### 精确文件、出处与原文

组合线索：唯一短语/标题 + 作者/机构；有编号、DOI、产品型号或文件名时保留。搜索引擎没有结果时，查已知机构的目录、站内搜索、引用文献或公开档案。

例如找某报告原始图表：先检索图题中的独特短语，再查报告发布者和年份，进入 PDF 核对图号、页码与图注。若只找到引用该图的文章，称其为转载线索。无法确定最初作者时，不声称已经找到“原始出处”。

### 素材、图片与模板

将主题和实际交付属性分开：主题 + `editable` / `SVG` / `PPTX` / `template` 等用户确实需要的属性。可用图片搜索时先定位视觉候选，再回到作者/素材详情页；预览缩略图不能证明原文件分辨率、矢量格式或可编辑性。

例如“找可编辑的实验流程图 PPT 模板”：尝试 `experimental workflow editable PowerPoint template`，根据命中的正式资源名进入文件页，核对实际是否 PPTX、是否仅是截图、是否需要付费及使用许可。没有精确匹配时，可返回“可编辑 SVG，但不是 PPTX”的明确替代项，不能自行生成一份后说找到了。

### 教程与软件项目

教程查询用“要做的动作 + 软件 + 版本”；项目查询用“功能 + 平台/语言 + 区分性条件”。不要把用户版本换成最新版；同时注意旧文档被重定向至最新版的情况。

进入教程正文核对必要步骤和前提，进入项目仓库核对所需功能的文档/示例及对应发布版本。README、功能演示和实际运行是不同证据，未运行时不声称“测试可用”。找现成脚本时交付仓库或相关文件入口，不能拿新写代码代替检索结果。

### 数据与统计资料

先明确指标口径、单位、地域、频率和时间范围，再用“指标/变量 + 覆盖范围 + 数据/表格/下载”查询，优先追踪生产或维护该数据的机构。

核对是否拿到了数据对象，而不只是新闻图、论文中的汇总表或数据集介绍。论文可作为发现线索，数据入口需另外核实。页面声明的覆盖范围与实际可读记录区分报告；下载、注册、申请访问等状态也分别说明。

## 不完全匹配与结束方式

若最终只有替代项，保留用户硬条件并明确差异，例如：“找到 SVG 可编辑版本；没有核实到你要求的 PPTX 版本。”不要用“差不多”掩盖缺项。

失败交付保持简短，通常包含：已搜索的主要路径、卡住的具体条件、最有希望的可核实线索。不需要输出全部搜索日志，也不能承诺穷尽全网。用户若指定了数量、时间或费用预算，优先遵守。
